## Non-negotiable behaviors now protected by tests
1. Guest/planning count changes recalculate recipe quantities and shopping demand.
2. Adding the same recipe twice does not duplicate its menu/dependency graph.
3. Homemade dishes generate scaled ingredient and prep requirements.
4. Purchased dishes stop generating homemade ingredients/prep and generate prepared-food requirements.
5. Confirmed guest-provided dishes stop generating host shopping/prep requirements.
6. Planned-but-unconfirmed guest contributions remain in host requirements.
7. Compatible ingredient units consolidate; incompatible mass/volume units never invent a conversion.
8. Removing one dish removes only demand generated by that dish.
9. Pantry and committed purchases are subtracted from current demand.
10. Purchases remain committed when demand falls; the engine reports coverage/surplus instead of erasing them.
11. Manual shopping items survive recipe recalculation.
12. UI is never the source of calculation truth.

## Testing rule
Each recovered rule gets a domain regression test before it is wired into the interface.
