# Customer release — 2026-10-03 UTC

This is the rebuild of `allygoodencrow-pixel/NEW-Thanksgiving`, based on main
`8588da30c5ab0773594270b314c63954e2394c4f`. It is not a second app or repository.

## What changed

The user-selected `Crow-Crown-Interface-Preview(4).html` is recovered into
`src/selected-interface.js` and its stylesheet. Images and Geist fonts are
extracted unchanged into `public/selected-interface`. The recovered artifact
includes its React runtime and planning engine; it is formatted for inspection,
but retains generated identifiers. Future UI edits should be made against this
selected interface, not the obsolete dark `src/app.js` entry point. The older
engine sources/tests remain for regression reference; their tests alone do not
prove parity with the recovered interface.

`src/main.js` now opens the customer account shell. Customers sign up with their
own email and password, confirm their email, and activate a single-use purchase
code. Each account gets one private Thanksgiving plan. Sign-in, sign-out,
password recovery, access activation, save-error recovery, and unsaved backup
export are implemented. New customers get setup, with no sample household.

The existing Supabase project `yqlomzvhtesstezyjair` supplies authentication,
subscriptions and snapshots. Only a public publishable key is bundled. The
migration is applied and recorded as `20261003052922_customer_accounts`.
Database saves use an atomic version predicate. Ownership comes from auth.uid(),
never a client-supplied owner. All save/redeem functions verify confirmed email
and authoritative entitlement state. Private privileged functions expose only
narrow caller-scoped operations. Customers cannot directly write subscriptions,
change snapshot versions, issue codes, or view the code table.

The customer draft stays in memory, not shared localStorage. Sign-out flushes
pending saves. A failed save freezes editing and offers download/reload;
network failure and version conflict are never reported as saved. Auth session
persistence is handled by Supabase separately from plan content.

## Seller fulfillment

Manual fulfillment is implemented. Automatic Shopify/Stripe fulfillment is
NOT connected because the sales product/provider has not been selected.
After a genuine paid order, an administrator can run in the Supabase SQL editor:

```sql
select customer_private.issue_access_code('YOUR-UNIQUE-PAID-ORDER-REFERENCE');
```

Deliver the returned code privately with that customer's purchase. The code is
shown once, stored only as a hash, and redeemable by one verified account. Do not
put it in this repository, browser code, screenshots, or public documentation.
An optional second timestamptz argument sets the access expiry. Null means
non-expiring access; choose the duration to match the actual product terms.

For a refunded/cancelled order:

```sql
select customer_private.revoke_access_code('YOUR-UNIQUE-PAID-ORDER-REFERENCE');
```

This invalidates the code and revokes its active subscription. Read and write
access checks consult the current database state. No browser-side unlock exists.
No production access codes were generated by the rebuild.
